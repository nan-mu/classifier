## 本轮复用的证据

- **发布对象到 angr 的预验证。** 作者在 Linux x86_64、Python 3.12.14、angr/claripy 9.2.176、pyelftools 0.32 通过 `angr.Project` 的 blob 后端及原型 Heimdall 分析三个无重定位对象。just_drop 得到一个 DROP 退出，两个 CAS2 程序各有三个正常出口，覆盖与正确规格为 UNSAT，错误版本为 SAT。复用原型与规格，不计入本轮正式 CLI 的路径或向量结果。[原型预验证](https://gitea.nas.nan-mu.cc/mcp/classifier/src/commit/7e4916149f71a136a5b7e0e65383337399cc3656/tests/release-v011.md#发布对象到-angr-的预验证)
- **旧后端的批处理基线。** 作者在开工 head、Linux x86_64、Python 3.12.14、Z3 4.15.4、7-Zip 25.01，用现有容器入口重放 v0.1.1，结果为 12 个程序、23/23 向量、53 个成立用例与 3 个预期反例。复用原附件的 23 组输入和独立保存的包及动作等期望。附件摘要核对为 `64e25d28e27daffb5c3df264749e95c79da808895195be04413aea8c58208e8f`。此基线仅用于对照。[旧后端记录](https://gitea.nas.nan-mu.cc/mcp/classifier/src/commit/7e4916149f71a136a5b7e0e65383337399cc3656/tests/release-v011.md#旧后端的批处理基线)
- **非法指令字段。** 作者在开工 head 用 Python 3.12 和 Z3 4.15.4 检查空包上的 MOV64 与 EXIT，保留字段 `offset=0` 和非法的 `offset=7` 都被判定成立。该结果作为失败基线，新对象入口分别验收合法 MOV 结果和非法 MOV 拒绝。[指令记录](https://gitea.nas.nan-mu.cc/mcp/classifier/src/commit/7e4916149f71a136a5b7e0e65383337399cc3656/tests/instruction-encoding.md)

## 本轮实测

在 Darwin arm64、Python 3.12.14、angr/claripy 9.2.176、Heimdall `90b4605e1c6ddae7ae5ead9738d5c1ff8e2843ad`、pyelftools 0.32、7-Zip 17.05、Z3 4.13.0 下，按 [仓库复跑命令](../../../../tooling/rbpf/README.md) 运行 `make_specs.py --release-objects`、`analyze.py release --tag v0.1.1` 和 `acceptance_objects.py --z3 z3`。正式输入是 SHA-256 一致的 12 个发布归档中的索引对象，向量使用原任务包的独立期望。

| 发布对象 | 通过的向量 | 路径或观察 |
| --- | ---: | --- |
| bsort | 2/2 | 合法请求 132 个回边，核对多轮后的完整包 |
| case_mark | 2/2 | 3 个出口，匹配路径 TX，偏移 77 写 1 |
| case_swap | 2/2 | 3 个出口，匹配路径 TX，偏移 77 写 2 |
| copy | 2/2 | 合法请求 155,913 条指令和 8,193 个回边，8,232 次包写入 |
| firewall | 2/2 | 命中 DROP，计数加一。未命中 PASS |
| fletcher32 | 2/2 | 合法和短请求的全包比较 |
| just_drop | 1/1 | DROP |
| just_tx | 2/2 | lookup 键 17，u32 从最大值回绕到零，MAC 交换 |
| log2 | 2/2 | 合法和短请求的全包比较 |
| noop | 2/2 | 合法和短请求的全包比较 |
| prime | 2/2 | 合法和短请求的全包比较 |
| strcmp | 2/2 | 合法和短请求的全包比较 |

- release 汇总 12 条 `analyzed`，23/23 个具体向量通过。CAS2 两个正确版本与 firewall 计数规格覆盖完整。两个错误版本和 firewall 错误计数均为 SAT，单对象 CLI 复放得到相同差异。
- copy 用零回边预算执行原合法向量，覆盖缺口 SAT，记录 `loop_budget` 和见证输入。此刻意截断实验独立于正式 23 组向量。
- 去掉 rBPF mode 和容器的档案使用原始 just_drop 对象，通过单项发布检查。错误归档摘要、截短 ELF 和无效 map 符号给出定位。单对象入口合法 MOV64 得到 DROP，`offset=7` 的 MOV64 在槽 0 被拒绝。
- Z3 5.1.0 独立复算 164 份查询，正式发布 35 SAT、93 UNSAT，复放和负向检查 13 SAT、23 UNSAT。7 项历史 Python 回归测试和 Python 编译检查通过。

## 审查后的检查

本地规格审查追踪了单对象入口、发布索引、BTF 和 angr 的执行及三个反例。仓库规范审查核对了 `.cursor/AGENTS.md`、锁定依赖、历史入口的兼容性及交付差异。

修正无符号除数为零的 VEX 路径，对非 XDP helper 调用和写入帧指针的编码拒绝装载，并拒绝依赖未定义数据的 lookup 键。两组构造对象在修订前未判定，修订后 DIV32 返回零、MOD32 保持原值。复跑实际涉及这些路径的 prime、firewall 和 just_tx，所有路径和用例 JSON 与全量结果相同。新校验下重新装载全部 12 个对象，对象与重定位后镜像摘要均与全量结果一致。其余九个程序不存在受影响的算术指令或 helper 调用，沿用全量执行结果。

历史发布入口仍报告 12 条缺容器。另用故意损坏的规格检查批处理错误边界，just_drop 得到 `byte offsets must be an object`，随后 just_tx 的两个向量通过。此诊断与正式验收分开。
