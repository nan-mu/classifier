# 资源读取与位置赋值

内容读取与资源位置赋值都写真实目标，但取得右值的来源不同。内容访问须满足[资源绑定前提](指令局部效果的前提.md)，位置赋值须有独立的位置绑定。

## 已绑定内容的读取

Stack、Map 的投影与扩展公式见[单元字段读写](单元字段读写.md)，Packet 的拼接与扩展见[包字节读写](包字节读写.md)。这些规则只写真实目标；源类别由唯一绑定决定。

RV32 的 LB、LH 读取 8、16 位并符号扩展；LBU、LHU 零扩展；LW、C.LW、C.LWSP 读取 32 位。目标宽度为 32。合法普通 LOAD 写 x0 时无目标赋值，仍须满足访问条件；C.LWSP 的零目标非法。窄读取确定整个目标，高位不保留目标旧值。

eBPF LDX MEM 对 8、16、32、64 位内容零扩展至 64 位；MEMSX 对 8、16、32 位内容符号扩展。LOAD_ACQ 采用普通零扩展的数值规则。这个投影没有 acquire、原子性或排序观察，不能由数值关系相同推导完整行为相同。

## 确定位置的赋值

LDDW 的资源位置或程序位置子类型需要

\[
\Gamma_{\mathrm{pos}}(i)=t_{\mathrm{bind}}\in\mathrm{Term}_{64},
\qquad E_i=\{r_d=t_{\mathrm{bind}}\}.
\]

绑定项不从 Map 内容等式取得，也不要求程序位置先存入另一真实寄存器。Map 或位置编号本身不确定地址。若只提供 32 位项而没有转换语义，不能直接写入 Real64，该分支无定义。位置绑定可靠性须另行证明。

普通整数 LDDW 见[常元赋值](常元赋值.md)。其他未定子类型见[规则定义域](../NodeInference/指令参数与规则定义域.md)。

数值依据为 [RV32I](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html)、[C 扩展](https://docs.riscv.org/reference/isa/v20260120/unpriv/c-st-ext.html)、[BPF ISA](https://docs.kernel.org/bpf/standardization/instruction-set.html)与 [LLVM 扩展定义](https://llvm.googlesource.com/llvm-project/+/17bfc00f7c4a424d7b5dc6da575865833701fd1a%5E%21/)。
