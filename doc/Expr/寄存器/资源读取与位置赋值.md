# 资源读取与位置赋值

内容读取与资源位置赋值都写真实目标。内容访问采用[指令结果的前提](../Expr.md#指令结果的前提)，位置赋值需要独立的位置绑定。

## 已绑定内容的读取

Stack、Map 与 Context 的对象身份见[寄存器定义](../../寄存器定义.md)，内容读取采用[字段投影与扩展](单元字段读写.md#单元字段读写)，Packet 读取采用[字节拼接与扩展](包字节.md#读取拼接与写入拆分)。源类别由指令集侧的地址绑定根据地址源寄存器的项及指令偏移确定。读取内容项并生成真实目标完整等式 \(\bar{E}_i\) 的取源与构造前提采用[访问参数与源项](单元字段读写.md#访问参数与源项)。

### RV32 内容读取

LB、LH 读取 8、16 位并符号扩展；LBU、LHU 零扩展；LW、C.LW、C.LWSP 读取 32 位。目标宽度为 32。合法普通 LOAD 写 x0 时无目标赋值，仍须满足访问条件。C.LWSP 的零目标非法。窄读取确定整个目标。

### eBPF 内容读取

LDX MEM 对 8、16、32、64 位内容零扩展至 64 位；MEMSX 对 8、16、32 位内容符号扩展。LOAD_ACQ 采用普通零扩展的数值规则。acquire、原子性或排序观察未定义，数值关系相同不足以确定完整行为相同。

## 确定位置的赋值

### eBPF 位置赋值

LDDW 的资源位置或程序位置子类型需要唯一的 64 位位置绑定。位置赋值要求本次访问取得唯一的位置绑定。绑定存在且唯一时，局部关系是真实目标 \(r_d\) 的完整等式 \(\bar{E}_i=\{r_d=t\}\)，其中 \(t\in\mathrm{Term}_{64}\)。
位置绑定缺失或不唯一时，该分支无定义，不生成成功效果。

绑定项不从 Map 内容等式取得。程序位置无需先存入另一真实寄存器。Map 标识或位置编号本身不确定地址。仅有 32 位项而无到 \([0,64)\) 的转换时，写入 \(\operatorname{Real}(r,[0,64))\) 的分支无定义。位置绑定可靠性须另行证明。

普通整数 LDDW 采用[常元赋值](真实寄存器.md#常元赋值)。其他未定子类型见[规则定义域](../../NodeInference/step.md#局部规则的合法域)。

数值依据为 [RV32I](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html)、[C 扩展](https://docs.riscv.org/reference/isa/v20260120/unpriv/c-st-ext.html)、[BPF ISA](https://docs.kernel.org/bpf/standardization/instruction-set.html)与 [LLVM 扩展定义](https://llvm.googlesource.com/llvm-project/+/17bfc00f7c4a424d7b5dc6da575865833701fd1a%5E%21/)。
