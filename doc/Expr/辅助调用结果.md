# 辅助调用结果

本文集中定义 helper Predicate 对应的值关系。调用身份、类型、参数与观察的构造见 [helper Predicate](../Predicate/辅助调用观察.md)；部分求值采用 [solve 的扩展](符号项求值与常量折叠.md)。

## 返回结果接口

从 Predicate 生成 Expr 的数学接口分为类型投影、参数投影、结果项与返回赋值：

\[
\begin{aligned}
\operatorname{helperKind}(p)&=h,\\
\operatorname{helperArgs}(p)&=\vec t,\\
\operatorname{helperResult}_{32}(p)&=\operatorname{solve}(F_{\varepsilon,h}(C_{32}(\operatorname{id}(h)),\vec t)),\\
\operatorname{helperExpr}(p)&=\{r_{\mathrm{ret}}=\operatorname{helperResult}_{32}(p)\}
\cup\operatorname{helperMapExpr}(p).
\end{aligned}
\]

\(F_{\varepsilon,h}\) 是带调用身份的未解释形式运算符，项签名为 \(\mathrm{Term}_{32}^{1+n(h)}\to\mathrm{Term}_{32}\)，数值解释的签名为 \(\mathbb B_{32}^{1+n(h)}\to\mathbb B_{32}\)。它的第一个实参是已确定类型的编号常元，因此即使 \(n(h)=0\) 也不需要零元运算符；这不增加待读取的参数寄存器。结果由[项解释补全](右值.md) \(\theta\) 提供数值含义，部分求值仍返回未知。不同事件即使类型与实参相同，也不要求结果相同。

每种 helper 可以分别细化 \(F_{\varepsilon,h}\) 的结果契约；在未给定契约时，不用常元零、调用前的 \(a_0\) 或其他参数替代结果。这里的 \(F_{\varepsilon,h}\) 表示该类型的返回投影：checksum 取结果低 16 位并以 32 位项承载，其他已支持类型保留完整 32 位结果。Map lookup 的附加关系见下文「lookup 返回关联」。

本次 helper 的寄存器值投影只写 \(r_{\mathrm{ret}}\)。调用指令自身的链接 Expr 另由控制规则产生，并与此更新组合。这个范围不构成对资源内容或调用约定下其他机器寄存器的完整保持证明；Map update/delete、包长度变化及其他外部副作用仍须另给契约。

对确定的未支持编号，返回项另定义为 \(C_{32}(2^{32}-1)\)，不应用未解释结果规则。

## lookup 返回关联

设调用前成功生成

\[
p=\operatorname{helper}(\varepsilon,\mathrm{MAP\_LOOKUP},(t_{\mathrm{map}},t_{\mathrm{key}})),
\qquad t_{\mathrm{ret}}=\operatorname{helperResult}_{32}(p),
\]

其中 \(\mathrm{MAP\_LOOKUP}\) 简记类型 `BPF_FUNC_MAP_LOOKUP_ELEM`。令 \(m_{\varepsilon,0}\in\mathrm{Reg}_{\mathrm{Map},32}\) 为本次返回关联的虚拟 Map 标记，其字节区间为 \([0,4)\)。定义真实寄存器变元 \(R_{32}^{\varepsilon}(a_0)\)，表示本次调用返回时由真实寄存器 \(a_0\) 承载的值。该变元与普通输入变元不同，身份由调用事件、寄存器类别、位宽和编号共同确定；它不查询后续时刻可变的 \(a_0\)。

定义附加 Map 关系：

\[
\operatorname{helperMapExpr}(p)=
\begin{cases}
\{m_{\varepsilon,0}=R_{32}^{\varepsilon}(r_{\mathrm{ret}})\},&h=\mathrm{MAP\_LOOKUP},\\
\varnothing,&\text{其他类型}.
\end{cases}
\]

这里 \(r_{\mathrm{ret}}=a_0\)。返回结果接口与本式共同给出 lookup 的真实返回等式和虚拟 Map 等式。

附加 Map Expr 的关系为完整等式，左侧为虚拟 Map 寄存器，右侧为承载返回值的真实寄存器变元。它不复制调用前 \(a_0\) 中的 helper 编号，也不把 \(t_{\mathrm{ret}}\) 直接作为右侧项。其他 helper 仅产生真实返回寄存器等式；调用指令自身的链接更新另行组合。

在给定解释下，调用结果契约要求 \(R_{32}^{\varepsilon}(a_0)\) 的赋值与本次返回项的解释一致。这个关联等式提供后续建立 Map 读写关系的入口，不单独给出实际 Map 内容、查询成功或位置有效性的证明。后续访问仍须确定对象、条目、偏移及有效范围；不同查询若可能指向同一条目，不能仅因调用身份不同就断言它们不别名。空返回不能作为有效内容访问。

后续为相应 Map 标记建立读写关系时，使用已有的寄存器、Term 与 Expr 更新规则，不增加通用地址解引用运算。访问的完整生成规则、多个调用关联的别名一致性及 update/delete 对既有关系的影响仍须独立规定。

**引理 M5（lookup 关联的结构有效性）。** lookup 产生两个互异键的 32 位完整等式，其中一个写真实返回标记，另一个建立虚拟 Map 关联；之后覆写 \(a_0\) 不改变已经构造的真实寄存器变元身份。

**证明。** Real 与 Map 类别不交，因此两个键不同。返回项与真实寄存器变元均为 32 位，与左侧位宽匹配。变元身份固定了调用事件与寄存器标记，后续覆写不修改已有项。\(\square\)

## 更新的结构性质

**命题 H2（返回更新的有限性与位宽）。** 对生成成功的 \(p\)，\(\operatorname{helperExpr}(p)\) 含真实返回键，lookup 另含一个虚拟 Map 键；集合有限、位宽匹配且键唯一，覆写不改变其余 Expr 键。

**证明。** 结果项与真实寄存器变元均为 32 位。lookup 的两个左侧分别属于 Real 与 Map，键互异；其他类型只有返回键。覆写结论由[按键覆写](关系集合按键覆写.md)的定义得到。此处仅证明所选值投影的结构性质。\(\square\)
