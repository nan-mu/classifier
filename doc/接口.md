# 接口

`create` 把执行前已经知道的值写成初始表达式。`step` 按当前指令和指令前状态生成后继，以及这一条指令的表达式和观察。`update` 把这一条指令产生的增量并进指令前状态。`history` 找出一段执行里哪些旧值可能影响分支或观察参数。

```lean
create  : Entry -> Except Failure State
step    : Program -> Pos -> State ->
          Except Failure (List (Dir × Loc × State))
update  : State -> State -> State
history : State -> List (Dir × State) -> List Reg
```

**`create`** 写入入口指针、栈指针、包的起止、上下文字段，以及 Map 的键长和值长。它们是真实寄存器或 Context 上的等式。需要读键或值的 Map helper，还要求长度等式能给出读取长度，并且缓冲区里要用到的字节已经有项。

RV32 的包数据是符号 `v32:4`，包长是符号 `v32:5`，包尾是 `add32(v32:4,v32:5)`。eBPF 的包数据同样从 `v32:4` 进入，包长在创建时取常数 128，包尾是 `add32(v32:4,128)`，再经 `zext`、`low` 和 `id` 放进 64 位计算。两端都没有一份单独的「公共包尾」项。

**`step`** 从指令前状态 \(\sigma_g\) 取源值和条件。分支的每个后继都从同一个 \(\sigma_g\) 生成，各自带着方向、后继位置和本步增量 \(\sigma_i\)。缺少操作数、不支持的指令，或后继无法确定，按该条规则拒绝，不当成空操作。这里支持的构造只覆盖该架构的一部分指令。

**`update`** 合并相交的绑定：覆盖的部分改绑新项，未覆盖的部分留下旧项的片段，使已定义区间不再重叠。分支条件作为约束保留，不变成赋值。本步观察并入已有观察。然后用新状态和后继位置继续 `step`。

**`history`** 的输入是入口状态，以及逐步的方向、表达式和观察。它返回要拿来比较的寄存器区间。循环第一次回到路径上已经出现的位置时使用它。它给出的清单是否包含了全部会改变分支或观察参数的旧值，仍是证明义务。引理 1 只刻画差集和这份清单之间的关系，不证明清单是完整的。
