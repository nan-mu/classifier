# 寄存器

表达式左侧的 \(\mathrm{Reg}\) 指出受约束的位置。区间 \([b,e)\) 是半开的，\(b<e\)，宽度是 \(e-b\)。

\[
\begin{aligned}
\mathrm{Reg}
::=\;&\operatorname{Real}(r,[b,e))\\
\mid\;&\operatorname{Stack}([b,e))\\
\mid\;&\operatorname{Map}(m,\bar k,[b,e))\\
\mid\;&\operatorname{Packet}([b,e))\\
\mid\;&\operatorname{Context}(j,[b,e)).
\end{aligned}
\]

**Real** 用当前架构的寄存器编号作身份。同一机器寄存器的别名仍是这个身份。指令的寄存器操作数和访问位数决定用哪一段。

**Stack** 是栈上的一段。eBPF 从帧指针及其派生地址定位，RV32 从 SP 以及仍保持这个栈来源的地址项定位。位置能够确定，不表示还没写过的内容已经有值。

**Map** 是某个键对应的值里的一段。地址项必须能追到 Map 查找 helper 的返回项，并且已经有一条记下 Map 标识和完整键字节的 Helper 观察。键长、值长用来判断访问是否落在值区域里。

**Packet** 是输入包上的一段。包起点来自上下文的 data 字段。地址项要能恢复包来源和相对起点的位移，再结合指令偏移和访问宽度定位。尚未写入的输入字节，第一次读取可以得到该字节的符号项。已经写过的区间用已有的项。

**Context** 是 XDP 字段，以及推演用的固定信息，例如某个 Map 的键长、值长和 helper 入口。Map 布局字段的身份里包含 Map 标识，用来区分不同的 Map。`create` 为已知项建立这些等式。

\(\mathrm{Reg}\) 的区间和项的片段按同一边界拆开。写入的起点或终点落在旧绑定内部时，没被盖住的部分保留原来的资源身份，只改自己的区间和对应片段。只读其中一段时，截取对应片段，原来的绑定不动。

当前具体入口是 ESP32-C3 上的 RV32IMC，ABI 为 `ilp32`，没有浮点寄存器。包数据指针在入口是 `v32:4`，包长是 `v32:5`。eBPF 一侧把这份长度写成创建时的常数 128，再在 64 位寄存器里传递 32 位字段。这些是 ESP32-C3 与 eBPF 这一对入口的约定。
