# 观察

观察记录要比较的程序行为。下面五类就是路径匹配所读的类别。路径匹配不读参数。

\[
\begin{aligned}
\mathrm{Observation}
::=\;&\operatorname{Helper}(h,\bar t)\\
\mid\;&\operatorname{Branch}(d,t_l,\mathrm{OP},t_r)\\
\mid\;&\operatorname{Return}(t)\\
\mid\;&\operatorname{MapWrite}(m,\bar k,o,w,t)\\
\mid\;&\operatorname{PacketWrite}(p,o,w,t).
\end{aligned}
\]

代码里的构造是 `helper`、`branch`、`ret`、`mapWrite`、`packetWrite`。

**Branch** 记录条件分支的比较和所选方向。eBPF 的条件跳转和 RV32 的 `BEQ`/`BNE`、`BLT`/`BGE` 等会生成它。操作数来自处理这条指令之前的表达式；立即数来自指令。跳转方向沿用原来的比较，不跳转方向用互补关系。这些约束不更新寄存器。比较项里可以有变元，不必先算出真假。

**PacketWrite** 和 **MapWrite** 记录包和 Map 值区域的写入。类别由地址项的来源决定。普通栈写入只更新绑定，不生成这两类观察。MapWrite 保存的是查找时记下的键字节，不是后来可能被盖掉的键缓冲区地址。

**Helper** 由 eBPF 的 helper 调用，以及 RV32 上目标为 helper 入口的 `JAL`/`JALR` 生成。参数按各自的接口约定从已有表达式取出。返回值写成一个符号项，绑到返回寄存器。实现里的 `helper` 还带展开事件。`externalResult` 是这个返回值的项，同样带事件和通道。

**Return** 记录正常返回。eBPF 的 `EXIT`，以及识别为最外层正常返回的 RV32 返回，才生成它。后继是出口，并不自动表示已经有一条 Return 观察。

观察参数在生成时取自当时的表达式。之后再写寄存器，不改已经保存的项。观察列表按结构去掉重复，保留原有顺序再接上新的观察。这份列表不是完整的事件轨迹，也不保留重复次数。

**命题 2（行为与观察的一一对应）** 固定受支持的指令、语义环境和所选方向，并满足规则的适用条件。\(B_i\) 是这一步要关注的行为，\(O_i\) 是这一步生成的观察。暂时不看参数里的项，只保留类别和每一次发生。生成规则给出的对应 \(f:B_i\to O_i\) 应当是双射：每个关注行为恰有一个观察，每个观察都有来源，不同的发生对应不同的观察。
