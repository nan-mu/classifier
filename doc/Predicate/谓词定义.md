# 谓词定义

比较关系见[Expr 比较关系](../Expr/Expr.md#比较关系)。比较与后继约束的指令处理见[比较指令处理](../NodeInference/Jump/待处理.md#比较指令处理)。

## 类型与结构相等

固定指令序列 \(\mathbf I\)，其谓词域为五类谓词的不交并：

\[
\mathrm{Predicate}_{\mathbf I}
:=\mathrm{Helper}\sqcup\mathrm{Branch}_{\mathbf I}\sqcup\mathrm{Return}\sqcup\mathrm{MapWrite}\sqcup\mathrm{PacketWrite}.
\]

其中 \(\sqcup\) 保留 Helper、Branch、Return、MapWrite 与 PacketWrite 的类别标签。五类的构造分别由[Helper谓词](Helper谓词.md#类型定义)、[Branch谓词](Branch谓词.md#类型定义)、[Return谓词](Return谓词.md#类型定义)、[MapWrite谓词](MapWrite谓词.md#类型定义)与[PacketWrite谓词](PacketWrite谓词.md#类型定义)维护。

Helper 包含 MapLookup、MapUpdate、MapDelete 与 OtherHelper，完整 Map 事件保存冻结字节数组，OtherHelper 保存统一为 32 位或统一为 64 位的参数项向量；载体与字节项由[Helper 共同定义](Helper谓词.md#类型定义)确定。\(\mathrm{Branch}_{\mathbf I}\) 的位置分量属于该指令序列的合法位置域，条件保留项位宽标签。\(\mathrm{Return}\) 保留 32 位或 64 位返回项的位宽标签。MapWrite 保留 Map 项与源项位宽及键长度标签；PacketWrite 保留源项位宽标签；两类写入均保存访问位宽，复合包目的项另保存整次访问记录。改变 \(\mathbf I\) 会改变 Branch 的位置域，因此谓词域是以 \(\mathbf I\) 为索引的类型族；无索引的 \(\mathrm{Predicate}\) 只在固定 \(\mathbf I\) 的语境中作为 \(\mathrm{Predicate}_{\mathbf I}\) 的简称，不能据此直接比较不同程序的位置标记。

同一 \(\mathrm{Predicate}_{\mathbf I}\) 中的两个元素结构相等，当且仅当类别相同且该类的构造分量分别结构相等：

- Helper：子类标签与调用事件身份相同；MapLookup、MapDelete 的 Map 项与冻结键数组分别相同，MapUpdate 还比较冻结值数组与 flags 项，OtherHelper 比较 helper 类型与参数向量。数组长度和顺序均参与比较。
- Branch：条件指令位置、方向及条件分别相同；条件的位宽标签、两端项与关系符均参与比较，关系符保留比较宽度。
- Return：返回项的位宽标签与项结构分别相同。
- MapWrite：Map 项位宽、源项位宽、键长度标签及写入事件身份、Map 项、完整键数组、元素内起始偏移、访问位宽、源项分别相同。
- PacketWrite：写入事件身份、包资源身份、常量起始偏移或复合目的记录、访问位宽、源项位宽与源项结构分别相同。

各类所含项的位宽、运算符、参数与变元身份仍参与结构比较。有限观察集合仍按这种相等去重，不以逻辑等价为商关系。调用身份、helper 类型与参数向量的判据用于 OtherHelper。

一项观察是一个 \(p\in\mathrm{Predicate}_{\mathbf I}\)，分别记录 helper 调用、选定方向的分支条件、最外层正常返回结果、Map 元素内写入或包写入。其解释分别见[Helper 各构造的事件解释](Helper谓词.md#类型定义)、[Branch 的条件与谓词解释](Branch谓词.md#条件与谓词的解释)、[Return 的返回结果解释](Return谓词.md#返回结果的解释)、[MapWrite 的写入事件解释](MapWrite谓词.md#写入事件的解释)与[PacketWrite 的写入事件解释](PacketWrite谓词.md#写入事件的解释)。两类写入的解释读取保存的访问位宽并使用固定小端约定；外部的项解释参数仍为赋值与解释补全，复合包目的地址还使用其所属解释中的包字节赋值。

状态观察分量为有限列表 \(P\in\mathrm{List}(\mathrm{Predicate}_{\mathbf I})\)，结构去重后按成员相等比较。step 执行前的谓词列表为 \(P_g\)，执行前的 Expr 列表为 \(E_g\)，新增的谓词分量为 \(P_i\)。create 的入口状态构造见[初态接口](../NodeInference/create.md)。

[step 的状态组合与后继准备](../NodeInference/step.md#准备全部后继状态)将五类局部观察按[结构并集](#结构并集)加入执行前集合。各类生成条件仍决定局部增量是否有定义；集合累积保留已生成的成员，不补出缺失观察。

## 跨架构规范观察

不同程序产物的观察比较使用[跨架构谓词的相等判断](跨架构谓词.md#相等)，先由各侧生成环境规范化为 `CrossPred`，再比较规范结果。同程序的结构相等与观察集合累积继续使用[原始分量判据](#类型与结构相等)。

规范化所需的入口包资源、冻结字节和访问元数据由[生成环境](跨架构谓词.md#生成环境)给定；Expr 只参与原始观察的取源，不进入跨侧谓词判断。M1 至 M6 的对应处理与证据由[不匹配类别的处理](跨架构谓词.md#不匹配类别的处理)维护，判断限度见[判断范围](跨架构谓词.md#判断范围)。局部观察列表的[保序对齐](跨架构谓词.md#保序最大对齐)还要求共同单射替换及匹配左观察的显式定义域覆盖，定理与有限证据范围见[证据普查](../NodeInference/跨架构比较.md#形式化证据普查)。

## 观察集合累积与可满足性

结构累积的定义域为同一固定程序 \(\mathbf I\) 下的两个有限观察集合；两者均属于 \(\mathscr F(\mathrm{Predicate}_{\mathbf I})\)。局部生成、入口有效性与历史来源的要求分别由所属规则维护。

**义务（观察解释与历史对应）。** 证明各方向的 Branch 增量、正常返回的 Return 增量、MapWrite 与 PacketWrite 的写入增量及 Helper 调用增量与实际指令和逐步记录对应，且入口观察满足同一程序和资源语境的合法域。两类写入保存宽度、源项与实际机器访问的联系仍须建立；保存宽度到规范字节的投影由 [CP-Bytes](跨架构谓词.md#cp-bytes-写入字节与冻结尾部)闭合。Return 的取源时点与 Exit 检查时点的一致性由[Return 的源项与后继一致性义务](Return谓词.md#证明义务)维护。结构累积的集合性质不提供这些语义证明。

### 结构并集

执行前集合 \(P_g\) 与本步骤局部集合 \(P_i\) 均属于 \(\mathscr F(\mathrm{Predicate}_{\mathbf I})\)，其合并为

\[
\boxed{\operatorname{mergePredicate}(P_g,P_i)
:=P_g\cup P_i.}
\]

同一结构谓词重复出现时只保留一次；不同调用和写入由各类事件身份区分。Branch 与 Return 的重复同结构成员也按此规则去重。

局部状态的组合更新与分支候选的处理见[准备全部后继状态](../NodeInference/step.md)。Expr 的更新见[关系集合按键覆写](../Expr/Expr.md#关系集合按键覆写)。

**命题 P2（有限性与累积性质）。** 若 \(\mathcal P,\mathcal Q,\mathcal R\) 为同一 \(\mathrm{Predicate}_{\mathbf I}\) 中的有限集合，则它们的合并仍有限。

这些集合满足以下包含与并集性质：

\[
\begin{gathered}
\mathcal P\subseteq\mathcal P\cup\mathcal Q,
\qquad \mathcal P\cup\varnothing=\mathcal P,
\qquad \mathcal P\cup\mathcal P=\mathcal P,\\
\mathcal P\cup\mathcal Q=\mathcal Q\cup\mathcal P,
\qquad (\mathcal P\cup\mathcal Q)\cup\mathcal R
=\mathcal P\cup(\mathcal Q\cup\mathcal R).
\end{gathered}
\]

**证明。** 合并元素来自两个有限集合。对任一 \(p\in\mathrm{Predicate}_{\mathbf I}\)，其属于合并结果当且仅当属于任一输入集合；逐式展开成员关系即可得到包含、单位元、幂等、交换与结合性质。\(\square\)

这些结论针对有限集合。列表表示保留已有成员的排列，再按局部列表次序追加首次出现的新成员；已有列表中的重复不主动删除。列表的结构相等还比较顺序和重复次数，而其集合解释仅比较成员。上述交换与幂等性质属于集合相等；完整指令更新的可交换性须另行证明。列表顺序不充当已证明的事件顺序，工程对应见[共同 Predicate JSON](../NodeInference/路径合并FFI.md#共同-predicate-json)。

### 已取得的源项不随寄存器覆写改变

**命题 P3（源项固定）。** 若 Helper 谓词已由调用时取得的参数项与所需冻结字节数组构成，则之后覆写取得这些项的寄存器或缓冲区不会改变此谓词及其在同一[赋值与解释补全](Helper谓词.md#解释参数) \((\nu,\theta)\) 下的解释。

**证明。** Helper 谓词包含构造时取得的有限项，Map 构造的字节数组按位置保存这些项。状态更新只替换 Expr 键并向观察集合加入元素，不修改旧项、子类标签或调用身份。OtherHelper 的类型与参数向量、Map 构造的 Map 项、键和值数组及 flags 因此均保持不变；固定赋值下的解释随之保持，字节冻结性质见[Helper 命题 H4](Helper谓词.md#数学性质)。\(\square\)

两次读取同一寄存器可以取得不同项。

Branch、Return、MapWrite 与 PacketWrite 同样保存构造时的项，Expr 覆写不删除任何类的旧观察。两类写入还保存访问位宽，其字节序固定为小端；各类解释保持的外部赋值条件由各所属正文维护。

### 累积不等于可行性求解

五类解释由[类型与结构相等](#类型与结构相等)所链接的各所属正文维护。完整路径条件的解释见[比较指令处理](../NodeInference/Jump/待处理.md)。观察集合的累积既不证明路径可满足，也不检测或删除不可行路径。

## 观察集合与历史顺序

调用次序及逐次状态由执行路径表达。事件顺序不属于观察集合的分量。

设同一路径上的两次 OtherHelper 调用具有不同身份 \(\varepsilon_1\ne\varepsilon_2\)，但 helper 标识 \(h\in H_{\mathrm{other}}\) 与已固定的实参序列 \(\vec t\) 相同；\(H_{\mathrm{other}}\) 的定义见[OtherHelper](OtherHelper谓词.md#类型定义)。最终观察集合 \(\mathcal P\) 为

\[
\mathcal P=\{
\operatorname{helper}(\varepsilon_1,h,\vec t),
\operatorname{helper}(\varepsilon_2,h,\vec t)
\}.
\]

两次调用的区分与累积见[Helper谓词](Helper谓词.md#数学性质)。

相同 \(\operatorname{helper}(\varepsilon,h,\vec t)\) 的累积规则见[结构并集](#结构并集)。若观察访问顺序或逐次输出，则须定义相应事件与观察序列。

比较的路径顺序与旧状态保存见[比较指令处理](../NodeInference/Jump/待处理.md)。当前关系的赋值覆写见[关系集合按键覆写](../Expr/Expr.md#赋值覆盖全部旧关系)。
