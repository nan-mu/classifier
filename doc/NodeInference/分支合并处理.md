# 分支合并处理

## 运行时与接口调用

整个推理过程由外部运行时组织：运行时接收输入，调用接口，保存状态，并决定下一个处理哪个节点；数学接口只计算各自的语义，不负责调度。

create 的入口假设与 step 的指令规则按目标架构给定。下面的驱动使用标准推理和 Taken推演。产品接口与数学契约的对应见[工程边界](路径合并FFI.md#共同接口与实现边界)。

- [create](create.md) 根据目标架构已有的入口项与假设，产生第一份完整状态 \(\sigma_0\)。
- [step](step.md#局部推理接口) 接收指令序列 \(\mathbf I\)、从 1 开始的序号 \(j\) 和执行前状态 \(\sigma\)。当前指令是 \(\mathbf I[j-1]\)。step 返回拒绝，或若干后继。每个后继带方向、后继序号和局部增量。
- 标准推理和 Taken推演只决定下一步读哪一条指令。它们不保存路径记录。保存记录是运行时的工作。
- history 在回到父指令且这次只给出 not_taken 时使用。它给出一份寄存器清单。merge 用这份清单比较新旧 not_taken 的表达式差。

## 判据

这一节是原先的精确配置判据。本节的驱动不调用它，也不再按合并步推进。

完整配置相等是既有精确配置共享的判据，即位置、Expression 分量与 Observation 分量分别相等。该判据的完备性见[定理一](Jump/证明义务-路径合并完备.md#定理一精确配置共享判据的完备性)，相等末配置的有限深度后续一致性见[定理二](Jump/证明义务-路径合并完备.md#定理二相等末配置的有限深度后续一致性)。

两侧在控制流中汇合时，先比较各自已组合的完整状态；互补约束、赋值覆写与观察保留的边界见[控制流汇合与当前状态](Jump/路径合并-接口契约.md#适用范围与推论边界)。精确比较未成功且仍有可推进候选时，保留两侧记录，按合并步继续推进；后续既有更新使完整配置相等时，可重新使用精确配置判据。判断和复用均不额外删除约束、观察或前缀记录。

更宽的合并拟从历史记录的状态变化判断 Expression 差异是否影响相关 Observation 的构造。差异与观察的依赖依据见 [History 的差异无关性](History.md#差异无关性的依据)，豁免的证明要求见[投影条件](Jump/路径合并-接口契约.md#语义参照)；已发生的观察的保留要求见[适用范围与推论边界](Jump/路径合并-接口契约.md#适用范围与推论边界)。这种差异判定及其行为保持证明尚未完成。

**尚待讨论：** 操作者原句在「影响相关 Observation 的构造和」之后截断，后续要求未给出；不补出判定条件或证明结论。相关未决义务见[路径合并的未决义务](Jump/路径合并-接口契约.md#未决义务)。

## 驱动

指令序列记为 \(\mathbf I=(i_1,\ldots,i_m)\)。\(i_j\) 是第 \(j\) 条指令，\(j\) 从 1 数到 \(m\)。一次推理还带着执行前状态 \(\sigma\)。create 给出入口的 \(\sigma_0\) 和起始序号。标准推理从那里开始，按序号读指令，再把这条指令交给 step。

后继状态由 step 的局部增量和执行前状态组合得到。组合规则仍是 [step 的状态变换](step.md#状态变换的组合)。

一次处理的结果是一个标签，或一个停止原因。标签表示下一次进入同名流程，并带上下一次的序号和状态。

### 标准推理

标准推理的参数是 \(\mathbf I\)、当前序号 \(j\) 和状态 \(\sigma\)。

1. 从 \(\mathbf I\) 读出 \(i_j\)。
2. 调用 \(\operatorname{step}(\mathbf I,j,\sigma)\)。
3. step 拒绝时，本次停止并带上拒绝原因。
4. step 给出一个后继时，后继序号是 \(j'\)，后继状态是 \(\sigma'\)。结果是标签「标准推理」，参数为 \(\mathbf I,j',\sigma'\)。后继是 Exit 时停止，这是正常返回。
5. step 同时给出 not_taken 和 taken 时，产生两个标签。not_taken 的后继序号是 \(j_N\)，状态是 \(\sigma_N\)，对应标签「标准推理」，参数为 \(\mathbf I,j_N,\sigma_N\)。taken 的后继序号是 \(j_T\)，状态是 \(\sigma_T\)，对应标签「Taken推演」。Taken推演记下父序号 \(j\)、父状态 \(\sigma\)、旧的 not_taken 状态 \(\sigma_N\)，以及循环剩余次数。循环剩余次数的初值是 128。标准推理的其他步骤不扣这个次数。

标准推理不进入 taken。step 没有后继，或后继不是上面两种形状时，停止。

### Taken推演

Taken推演从 taken 的序号 \(j_T\) 和状态 \(\sigma_T\) 开始。运行时保存父序号 \(j\)，以及这段 not_taken 上逐步留下的 \((E_i,O_i)\)。taken 这一侧的每一步都先看当前序号是不是 \(j\)。

当前序号不是 \(j\) 时，结果是标签「标准推理」，参数是当前序号和当前状态。之后的分叉仍按标准推理处理。

当前序号回到 \(j\) 时，用回到这里时的状态对 \(i_j\) 再调用一次 step。

- 这次又同时给出 taken 和 not_taken。报错退出。
- 这次只给出 not_taken。调用 history。输入是这段 not_taken 的 \((E_i,O_i)\) 和旧 not_taken 状态的入口值绑定。输出是一份可忽略寄存器列表。被写过的寄存器进入这份列表，仅当观察项不依赖它的入口值：依赖包括观察中的 `regVar`，以及经入口绑定回指到该寄存器的变元及其派生项。重复写入本身不使它可忽略。新的 not_taken 和旧的 \(\sigma_N\) 先按位段对齐值绑定。有差异的位段若都在这份列表里，这条 Taken推演停止，两次 not_taken 的观察生成一致。否则新的 not_taken 继续标准推理。
- 这次只给出 taken。循环剩余次数减 1。减完仍有剩余时，结果是标签「标准推理」，参数是这个 taken 后继的序号和状态。剩余次数已经是 0 时，报错退出。

step 拒绝时，停止并带上拒绝原因。后继是 Exit 时，停止，这是正常返回。

### 两侧再出现与循环次数

回到父指令后又同时给出 taken 和 not_taken 时，代码报错退出。这条路径按下面两段理解。

走 taken 时，该方向的后继带上这条比较约束。约束行还在父指令的执行前状态里时，条件判断应当只有一个方向。现行 step 的部分判定只看比较两端能否算出确定数值，不读取已经保存的约束行，所以这一句还没有从现行 step 证出。`Node.live_constraint_excludes_both` 把这一句记成决策规则必须满足的前提。

约束行会被后来的赋值删掉。删掉之后，用 Linux BPF 检查器的结论作为人为定理：检查器接受的程序，回到同一条父指令并只给出 taken 的次数有限。依据是 `kernel/bpf/verifier.c` 的 `do_check` 与 `is_state_visited`：回边状态已被覆盖则剪枝，探索不能结束则拒绝程序。`Node.bpfLoopBound` 是这次接受所给出的次数。`Node.loop_limit_not_exhausted` 说明，循环剩余次数的初值不低于这个次数时，剩余次数不会被减完。它不说明 128 对每个被接受的程序都够。检查器在标量范围仍跨在条件两侧时，仍会再展开两个方向；因此「约束被删掉之后两个方向不会再出现」还不是检查器的定理。代码仍然在两个方向同时出现时报错退出。

### 和原来的合并说明的关系

观察生成一致只比较 history 给出的寄存器列表。驱动不调用精确配置比较。

Lean 里 history 是 `Node.history`。标准推理的一步是 `Node.driveStandard`，Taken推演的一步是 `Node.driveTaken`。人为定理在 `Node/BpfBound.lean`。文档里的 \(j\) 从 1 开始。代码里的序号从 0 开始。`driveTaken` 不自己沿指令列表循环。运行时在 taken 一侧每一步调用它，才能发现序号回到父指令。\((E_i,O_i)\) 由运行时按步传给 `driveTaken`。循环剩余次数也由运行时传回下一次 `driveTaken`。
