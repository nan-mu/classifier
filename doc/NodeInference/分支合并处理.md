# 分支合并处理

## 运行时与接口调用

整个推理过程由外部运行时组织：运行时接收输入，调用接口，保存状态，并决定下一个处理哪个节点；数学接口只计算各自的语义，不负责调度。

- [create](create.md) 根据目标架构已有的入口项与假设，产生第一份完整状态 \(\sigma_g=(E_g,P_g)\)；该初态在 create 中记为 \(\sigma_0\)。
- [step](step.md#局部推理接口) 接收 \((\mathbf I,j,\sigma_g)\)，其中 \(j\) 从 1 开始，当前指令为 \(\mathbf I[j-1]\)；返回拒绝或候选数组 \([(d_k,j_k,\sigma_k)]\)，\(\sigma_k=(E_k,P_k)\) 是局部语义增量。
- [history](History.md#逐步记录与统一类型) 从运行时保存的入口状态与语义变化构造历史；两侧使用同一类型，历史本身不证明路径合法。
- [merge](Jump/路径合并-接口契约.md#输入) 接收两侧的历史与相关信息。在 NotTaken 方向继续、Taken 方向执行若干条指令后回返到同一条件位置的情形，运行时提供 NotTaken 历史与 Taken 信息，交给 merge 判断两条路径能否合并，以及 Taken 回返是否是需要特殊处理的循环。

## 判据

完整配置相等是既有精确配置共享的判据，即位置、Expr 分量与 Predicate 分量分别相等。该判据的完备性见[定理一](Jump/证明义务-路径合并完备.md#定理一精确配置共享判据的完备性)，相等末配置的有限深度后续一致性见[定理二](Jump/证明义务-路径合并完备.md#定理二相等末配置的有限深度后续一致性)。

merge 从历史记录的状态变化判断某些 Expr 差异是否影响相关 Predicate 的构造，而不是结构比较两份完整 Expr 集合或把行为集合比较作为其目的。差异与谓词的依赖依据见 [History 的差异无关性](History.md#差异无关性的依据)，既有豁免的证明要求见[投影条件](Jump/路径合并-接口契约.md#语义参照)；已发生的观察的保留要求见[适用范围与推论边界](Jump/路径合并-接口契约.md#适用范围与推论边界)。

**尚待讨论：** 操作者原句在「影响相关 Predicate 的构造和」之后截断，后续要求未给出；不补出判定条件或证明结论。相关未决义务见[路径合并的未决义务](Jump/路径合并-接口契约.md#未决义务)。

## 驱动

### 入口

create 构造初始语义状态，见 [create](create.md)。

### 单步处理

外部运行时给定当前指令位置与执行前状态，处理顺序如下。

1. 调用 step 的一步局部处理，取得拒绝或携带方向、后继位置和局部语义增量的候选数组，见[局部推理接口](step.md#局部推理接口)。运行时保存该步的语义变化并写逐步记录，见[逐步记录与统一类型](History.md#逐步记录与统一类型)；增量与输入状态的组合归属见[尚待讨论的状态组合](step.md#状态变换的组合)。
2. 结果为拒绝时报告拒绝依据，见[无定义时的处理](step.md#无定义时的处理)。
3. 按[候选的分类与处置](#候选的分类与处置)处置。

### 候选的分类与处置

候选的目标是否为 Exit 与方向分类无关。Exit 候选的返回寄存器完整等式由[准备全部后继状态](step.md#准备全部后继状态)检查；取得入口状态与有限逐步记录后，调用 [history](History.md#逐步记录与统一类型) 构造正常返回历史，来源与组合前提见[历史构造](step.md#历史构造)。其余候选按方向数分类处置。

1. 空候选：只在[局部推理接口](step.md#局部推理接口)规定的条件下结束本次处理。
2. 单个候选且方向为 [OK](路径.md#方向与后继)：保存其局部语义增量，并继续处理其后继位置；后继全局状态的组合归属见[状态变换的组合](step.md#状态变换的组合)。
3. 单个候选且方向为 Taken 或 NotTaken：与前者相同，该候选携带的比较约束与谓词增量作为语义变化保存。
4. 两个候选，方向分别为 Taken 与 NotTaken：进入[分支处理](#分支处理)。

### 分支处理

处理一次条件分支的顺序如下。

1. 先推进 NotTaken 侧，不立即推进 Taken 侧。
2. NotTaken 侧推进结束后，由该侧的入口状态与逐步记录调用 [history](History.md#逐步记录与统一类型)，并按合并接口的[输入](Jump/路径合并-接口契约.md#输入)构造 \(\mathcal B_N\)，其入口状态为 \(C_b\) 的状态，第一条记录的执行位置为 \(j_b\)，方向为 NotTaken。
3. 推进 Taken 侧；当它执行若干条指令后回返到同一条件位置 \(j_b\) 时，由该侧的入口状态与逐步记录调用 history 并构造 \(\mathcal B_T\)。
4. 按[输入](Jump/路径合并-接口契约.md#输入)调用 merge，再按[合并结果的处置](#合并结果的处置)处置。

\(j_b\) 为本次分支位置，\(C_b\) 为该次分支的执行前配置，\(\mathcal B_N\) 与 \(\mathcal B_T\) 的分量与证据要求见该接口的[输入](Jump/路径合并-接口契约.md#输入)。合并只决定是否免除重复的后缀推理，不产生新的 Expr 或 Predicate，也不改写两侧状态，见[运行时对结果的解释](Jump/路径合并-接口契约.md#运行时对结果的解释)。

### 合并结果的处置

- \(\operatorname{Merged}(M)\)：可以合并。在既有契约的证据范围内，对 \(A_M\) 内的配置引用 \(R_N\) 指定的后缀免除重复后缀推理，两侧各自保留前缀与状态；该分支处理结束。
- \(\operatorname{Escape}(W)\)：回返需特殊处理。既有循环准入成立时，该 Taken 引用范围交给承担 \(F\) 的特殊循环处理，保留差异 \(\Delta_F\) 与循环内、退出后的义务；该范围作为一条独立路径保留。
- \(\operatorname{Reject}(a)\)：该次比较不获得复用或循环准入许可。依据为证据不足且 Taken 侧仍有待处理配置时，继续推进该侧并按同样顺序再调用 merge；依据为已证反例时结束该次比较。保留已有记录并报告依据。

**尚待讨论：** merge 是否在「可以合并」与「回返需特殊处理」之外保留第三类结果，操作者尚未说明；既有[结果类别与保证](Jump/路径合并-接口契约.md#结果类别与保证)为证据不足或已证反例声明了 \(\operatorname{Reject}(a)\)，此处保留该约定待核对。

既有三类结果允许的运行时动作与禁止推论由[运行时对结果的解释](Jump/路径合并-接口契约.md#运行时对结果的解释)规定。

### 驱动需要的输入与产出者

下列输入由外部产出。

1. 每一步的有序局部结果：由一步局部处理取得并由运行时保存，见[step 的候选输出](step.md#输出)与 [History 的逐步记录](History.md#逐步记录与统一类型)。
2. 两侧的覆盖包装与其证据、复用凭据与循环凭据：\(D_N\)、\(e_N\)、\(A_T\)、\(e_T\)、\(A_M\)、\(\kappa_M\)、\(e_M\)、\(F\)、\(\Delta_F\)、\(e_F\) 由独立的证明模块产出并交给驱动；其义务见[未决义务](Jump/路径合并-接口契约.md#未决义务)。
3. 循环处理的适用域、递减量、比较关系与内外义务：由[循环准入](Jump/路径合并-接口契约.md#escapew)规定的凭据给出；递减条件的发现见[适用范围与推论边界](Jump/路径合并-接口契约.md#适用范围与推论边界)。
