# 跨架构比较

## 输入与对应假设

一侧展开结果记为

\[
R=(a,N,G).
\]

其中 \(a\) 是非空架构名称，\(N\) 是非空有限节点序列，\(G\) 是有限边序列。节点保存不透明自然数引用、位置和已组合的全局语义状态；边保存源引用、方向和目标引用。节点与边的数学对象见[路径](路径.md)，状态分量见[step 的语义状态](step.md#语义状态)。create、step、预算快照的产品输出经外部运行时收集为此输入；快照的调度状态、失败原因、工作队列与预算不参与比较。

同侧节点引用必须唯一，全部边端点必须属于该侧节点序列。不同节点可以在相同位置；引用只用于解析边端点。方向取 `OK`、`Taken`、`NotTaken`。普通 `loc` 按[合并线协议的位置规则](路径合并FFI.md#请求对象)解析为非负十进制整数；`exit` 是独立结束位置。比较不检查位置是否属于某个真实程序。

**假设 C-A（同程序与表示对应）。** 调用方声明两份展开结果来自同一源程序的两个架构产物，并声明相同 `loc` 标签作为本次比较的表示对应。RV32IMC 的标签是解码后的零基指令下标，eBPF 的标签是零基原始 64 位槽下标；二槽 `LDDW` 的继续槽仍占原始槽位置。这是两个不同的索引空间。相同整数的对齐只执行调用方声明的表示对应，不证明两条指令、执行前状态或控制点相对应。外部运行时负责产物来源、入口与静态绑定的联系，以及该表示对应的可靠性证明。

`arch` 只保存名称。它不接受架构白名单校验，不决定项解释、寄存器映射或返回位宽，也不作为 C-A 的证据。接口允许同一展开结果与自身比较。

## 跨架构谓词判断

跨侧观察使用[CrossPred 相等](../Predicate/跨架构谓词.md#相等)：各侧先从真实生成来源取得 [CrossEnv](../Predicate/跨架构谓词.md#生成环境)，将原始 Predicate 规范化，再比较规范结果。M1 至 M6 的类型、规则及证明由[跨架构谓词](../Predicate/跨架构谓词.md#不匹配类别的处理)维护。

Expr 的值绑定和约束只参与各侧执行及原始观察取源，均不属于这个谓词判断。需要写入元数据的观察按其产生指令分别取得环境；完整冻结字节来自原始调用观察或写入来源，不能由 ABI 指针文本代替。节点覆盖、控制点与静态资源对应仍使用 C-A 及所属证明义务。

以下位置汇总与七类别差集描述既有结构报告接口。该接口的实现状态与规范谓词判断的差异由[实现状态](#实现状态)单独维护。

## 位置对齐

对侧 \(s\in\{L,R\}\) 和位置 \(\ell\)，同位置节点集合记为

\[
N_s(\ell)=\{n\in N_s:n.\mathrm{loc}=\ell\}.
\]

这里 \(L,R\) 分别指左、右输入；集合元素以同侧唯一节点引用区分，保留重复到达的节点数。

全部报告位置为

\[
\mathcal L=\{n.\mathrm{loc}:n\in N_L\}\cup\{n.\mathrm{loc}:n\in N_R\}.
\]

`positions` 每个元素含 `loc`、`verdict`、`leftNodes`、`rightNodes`。计数分别为 \(|N_L(\ell)|\)、\(|N_R(\ell)|\)。两侧均非空时 `verdict:"Both"`；只有左侧非空时为 `OnlyLeft`；只有右侧非空时为 `OnlyRight`。后两类只报告位置和计数，不出现 `control` 或 `classes`。

普通位置按解析后的整数递增排列，`exit` 最后。解析到相同整数的标签合并为同一报告位置，并输出规范十进制字符串。

## 控制与类别比较

同位置出边集合为

\[
O_s(\ell)=\{(d,\ell'): (u,d,v)\in G_s,\ \mathrm{loc}(u)=\ell,\ \mathrm{loc}(v)=\ell'\}.
\]

其中边端点先由同侧引用解析，\(d\) 为边方向，\(\ell'\) 为目标位置。`control.membersLeft`、`membersRight` 分别输出此集合，以 `"<dir>-><destination loc>"` 表示成员，例如 `"Taken->12"` 或 `"OK->exit"`。`control.onlyLeft`、`onlyRight` 分别为两个出边集合的定向差集。`control.verdict` 在两侧节点数相等且出边集合相等时为 `Equal`，其余为 `Differs`。不同方向参与集合成员身份；相同位置间同方向的多条边只保留一个控制成员。

既有结构报告的类别顺序固定为 `valueBindings`、`constraints`、`helper`、`branch`、`ret`、`mapWrite`、`packetWrite`。前两类分别取 `ExprSet.entries`、`ExprSet.constraints`；后五类按原始 Predicate 构造分类。各类的对象定义和同程序相等方式分别归[表达式分量](../Expr/Expr.md#表达式分量)与[谓词类型和结构相等](../Predicate/谓词定义.md#类型与结构相等)。这七类诊断不充当[规范谓词判断](#跨架构谓词判断)。

对类别 \(c\)，同位置的成员集合为

\[
S_{s,c}(\ell)=\bigcup_{n\in N_s(\ell)}\mathrm{members}_c(n.\mathrm{state}).
\]

\(\mathrm{members}_c\) 取得指定状态分量或指定 Predicate 类的全部成员。同位置多节点使用各类并集；报告保留节点数量，但不保留某个成员属于哪个节点的信息，不建立逐节点配对。

`classes` 的每个元素含 `class`、`verdict`、`leftCount`、`rightCount`、`onlyLeft`、`onlyRight`。计数是两侧该类去重后的成员数，差集使用结构相等：

\[
D_{L,c}(\ell)=S_{L,c}(\ell)\setminus S_{R,c}(\ell).
\]

其中 \(D_{L,c}\) 对应 `onlyLeft`，交换 \(L,R\) 得到 `onlyRight`。两集合相等时为 `Equal`，包括两侧均空；仅左侧为空时为 `AbsentLeft`；仅右侧为空时为 `AbsentRight`；两侧非空且不相等时为 `Differs`。

集合成员判定直接使用 [ExactConfig 的结构比较](路径合并FFI.md#比较规则)。值绑定键、角色、项构造、位宽、参数、身份及条件全部保留；项参数与键数组仍按内部次序比较。比较前不求解项、不重命名、不投影、不改变解释。输入节点内部的重复值绑定键或重复约束仍按共享状态合法性规则拒绝；Predicate 重复成员与跨节点相同成员按集合处理。

## 整体结论与性质

令 \(K\) 表示存在单侧报告位置，或某个共有位置的出边集合不相等。令 \(Q\) 表示每个位置均为 `Both`，且其 `control` 和全部类别均为 `Equal`。整体结论定义为

\[
\mathrm{conclusion}(R_L,R_R)=
\begin{cases}
\texttt{coverageDiffers},&K,\\
\texttt{sameStructure},&\neg K\land Q,\\
\texttt{differs},&\neg K\land\neg Q.
\end{cases}
\]

单侧存在的控制边优先归为覆盖差异；节点数量不同但该位置两侧都存在且出边覆盖相同，则由 `control:Differs` 归为 `differs`。`left`、`right` 同时保存 `arch`、`nodeCount`、`edgeCount`；这两个计数是输入节点和边的条数，边序列的重复不改变集合比较。报告固定 `status:"compared"`、`claim:"structural"`、`behavioralEquivalence:"notEstablished"`。

**命题 C1（自比较）。** 对任意合法输入 \(R\)，\(\mathrm{conclusion}(R,R)=\texttt{sameStructure}\)。

**证明。** 每个报告位置在两侧均存在，节点数相等。每个出边集合与其自身相等，每个类别并集与其自身相等，所有定向差集为空。因此 \(K\) 为假，\(Q\) 为真，整体结论按定义为 `sameStructure`。\(\square\)

**命题 C2（交换对称性）。** 对任意两个合法输入，交换两侧不改变整体结论；位置的 `OnlyLeft` 与 `OnlyRight` 互换，各差集的 `onlyLeft` 与 `onlyRight` 互换，各类别的 `AbsentLeft` 与 `AbsentRight` 互换，所有计数与架构名称交换归属。

**证明。** 位置并集不变；集合相等与计数相等均为对称关系，故 \(K,Q\) 不变。定向差集、单侧存在条件和单侧为空条件交换两侧后分别交换，得到所述字段变化。\(\square\)

这些是定义层面的命题；[Lean 实现](../../PathMerge/Compare.lean)的有限 `#guard` 与[真实产物检查入口](../../CrossArchCheck.lean)检验有限实例，不代替一般形式化定理。

## 语义范围与未决义务

`sameStructure` 只说明当前表示中按位置汇总后的结构相等；它不建立行为等价、逐节点状态对应、事件顺序对应、观察齐备或完整执行覆盖。`Differs` 及 `coverageDiffers` 也不构成行为不等价的反例。两种架构的中间关系集合未被主张相等，依据见 [Expr 单关系解释保持的范围](../Expr/Expr.md#关系解释)；Expr 差异与所关注谓词是否相关须遵循 [History 的差异无关性依据](History.md#差异无关性的依据)。

已明确的跨架构生成参数包括 [Return 的 \(A\in\{\mathrm{RV32IMC},\mathrm{eBPF}\}\) 与 \(w_{\mathrm{ret}}(A)\)](../Predicate/Return谓词.md#类型定义)，以及 [PacketWrite 的架构输入参数](../Predicate/PacketWrite谓词.md#生成条件)。这些参数规定各自构造的取源与位宽，不建立两架构行为对应。Branch 的两架构指令、保留方向及对应条件仍受[待证明义务](../Predicate/Branch谓词.md#待证明义务)约束。

`openObligations` 以所属文档锚点列出尚未由本接口提供的证据：

- [同程序与表示对应假设 C-A](#输入与对应假设)。
- [定理一的精确配置共享范围](Jump/证明义务-路径合并完备.md#定理一精确配置共享判据的完备性)、[定理二的有限深度后续一致性](Jump/证明义务-路径合并完备.md#定理二相等末配置的有限深度后续一致性)与其[前提 P1 至 P4](Jump/证明义务-路径合并完备.md#充分性前提)。这些定理针对共同程序与语境，不能直接用于两种架构的指令序列。
- [合并契约的未决义务](Jump/路径合并-接口契约.md#未决义务)。
- [History 的 H-O1、H-O2](History.md#控制流与记录来源)、[H-O3](History.md#完整依赖提取)、[H-O4](History.md#局部结果顺序与重复事件)。
- [Branch 的对应义务](../Predicate/Branch谓词.md#待证明义务)及[合并 FFI 的语义范围与证据边界](路径合并FFI.md#语义范围与证据边界)。

## 实现与线协议

[PathMerge.Compare](../../PathMerge/Compare.lean) 导出 Lean 运行时 ABI 符号 `lean_compare_run_same_diff`，对应 `PathMerge.exportCompareRunSameDiff : String → String`。外部运行时提交 C-A 的声明并负责其证据；该请求不携带或产生对应证明。

请求对象的必填字段为 `left`、`right`。两侧必填 `arch`、`nodes`、`edges`；节点必填 `id`、`loc`、`exprs`、`predicates`；边必填 `src`、`dir`、`dst`。例如：

```json
{"left":{"arch":"rv32imc","nodes":[{"id":0,"loc":"0","exprs":[],"predicates":[]}],"edges":[]},"right":{"arch":"ebpf","nodes":[{"id":7,"loc":"0","exprs":[],"predicates":[]}],"edges":[]}}
```

可以直接在产品快照对象上附加 `arch`；`status`、`reason`、`failed`、`fuel`、`work` 等额外调度字段不改变比较。`exprs`、`predicates` 通过共享 `ClassifierExpr.parseSemStateJson` 解析；Expr 项与关系范围继续使用 ExactConfig 的有效性检查。

成功响应具有[整体结论](#整体结论与性质)规定的四个固定字段及 `conclusion`、`left`、`right`、`positions`、`basis`、`openObligations`。`basis` 链接[表达式分量](../Expr/Expr.md#表达式分量)、[谓词结构相等](../Predicate/谓词定义.md#类型与结构相等)、[ExactConfig 比较规则](路径合并FFI.md#比较规则)与[控制和类别定义](#控制与类别比较)。位置及固定类别次序按前述定义排列；成员与差集先按结构去重，再按共享渲染结果的字符串顺序排列，控制成员与锚点字符串按字符串顺序去重排序。Expr、Predicate 差集复用共享渲染器，约束行保留 `role:"constraint"`。项内部参数次序保持原样。相同请求的响应字节完全一致。

任一无效输入拒绝整个比较，不产生部分报告。拒绝响应沿用合并诊断：

```json
{"status":"reject","reason":"InsufficientEvidence","detail":"InvalidLocation:left[nodes][3]"}
```

`detail` 的拒绝标签及触发条件为：

- `InvalidRequestJSON:<parser error>`：请求不能解析为 JSON。
- `MissingOrInvalidField:<field>`：必填字段缺失或类型错误，或 `arch` 为空字符串。字段路径如 `left[arch]`、`right[nodes][3][id]`。
- `InvalidLocation:<label>`：位置字符串不能解析为非负整数或 `exit`。
- `InvalidSnapshot:<label>`：共享状态解析失败，或 Expr 项、关系范围无效。
- `DuplicateNodeId:<label>`：同侧节点引用重复。
- `InvalidDirection:<label>`：边方向字符串不属于规定方向域。
- `UnknownEdgeEndpoint:<label>`：边的源或目标引用不在该侧节点中。
- `EmptyRun:<label>`：该侧节点数组为空。

这里 `<label>` 为 `left`、`right` 或具体节点、边路径，如 `left[nodes][3]`、`right[edges][2]`。实现先完整解析左侧，再完整解析右侧；报告仅在全部节点、边均通过检查后构造。多项错误时输出这一固定解析顺序首先遇到的诊断。

### 实现状态

`ClassifierExpr.CrossPred` 提供纯规范化、规范 JSON 渲染及 Lean 运行时 ABI 符号 `lean_cross_pred_normalize`，对应 `ClassifierExpr.exportCrossPredNormalize : String → String → String`。成功时返回恰为 `renderCrossPredJson (toCross env p)` 的字节，不附加包装；任一解析或环境失败返回四字符字符串 `null`。当前 `PathMerge.RunCompare.compare` 及 `lean_compare_run_same_diff` 仍按 `predicateClass` 分桶，以 `ExactMerge.sameSet` 比较原始结构；既有报告还包含 Expr 两类。它们尚未调用 `toCross`，所以 `sameStructure`、原始谓词差集以及 host 的指纹 LCS 不能视作规范谓词判断的运行结果。该偏差登记于 `.audit/lean-divergences.md`；文档链接、锚点和位置门均不检查此调用路径。

外部 host 切换到规范判断时须调用归一化 ABI、取得并提供各侧环境，并按规范输出的外层标签分桶。Helper 更新、删除可输出 `mapWrite`，因此不能继续以源 Predicate 标签决定规范观察类别。M6 的源观察生成缺口见[MapWrite](../Predicate/MapWrite谓词.md#跨架构变更观察与生成缺口)与[Helper](../Predicate/Helper谓词.md#跨架构调用观察)；单凭切换渲染器无法补齐这些源观察。

### 归一化 FFI 与环境线协议

[ClassifierExpr.CrossPred](../../ClassifierExpr/CrossPred.lean) 导出 `lean_cross_pred_normalize`。Lean 签名为：

```lean
ClassifierExpr.exportCrossPredNormalize (envJson predJson : String) : String
```

这是两个 boxed Lean `String` 输入、一个 boxed Lean `String` 输出的运行时 ABI。`envJson` 先经 JSON 解析及 `parseCrossEnvJson : Lean.Json → Option CrossEnv` 得到 `env`；`predJson` 经 JSON 解析及 `parsePredicateJson` 得到 `p`。成功输出恰为 `renderCrossPredJson (toCross env p)` 的字节，无响应包装。任一 JSON 解析、环境字段或 Predicate 解析失败均返回四字符字符串 `null`，沿用 `lean_virtual_cell_access` 的失败约定；这是 ABI 的字符串失败标记，不是返回一个 JSON `null` 值。

`envJson` 必须是对象。全部键均可省略，未知键拒绝并返回 `null`；缺省字段保留 `CrossEnv` 的默认值。允许字段如下：

- `packetBase`、`packetEnd`：共享 Meta 项语法的字符串，由 `parseTerm` 解析，未注明载体时使用默认 `.w32`。环境保留解析得到的 `Term`，`toCross` 使用时经 `toCrossTerm` 规范化。缺省值均为 `none`；显式 JSON `null` 不合法。
- `maps`：数组，缺省值为 `[]`。每个元素必须是对象，恰含 `map`、`keyBytes`、`valueBytes` 三个键。`map` 是由 `parseTerm` 解析后经 `toCrossTerm` 规范化的项字符串，作为静态资源绑定比较；`keyBytes`、`valueBytes` 是 JSON 非负整数，解析为 `Nat`。缺键、额外键或类型错误均拒绝。
- `storeBytes`：JSON 非负整数，解析为 `Nat`，缺省值为 `none`。
- `storeBigEndian`：JSON 布尔值，缺省值为 `false`。这是建议环境 schema 之外的扩展，使 `CrossEnv.storeBigEndian` 可由线协议指定。

`predJson` 是 `parsePredicateJson` 接受的单个原始 Predicate 对象，属于 helper、branch、ret、mapWrite、packetWrite 五类线协议，并须通过 `predicateWellFormed`。它携带原始项字符串及该类要求的载体、位置或事件等字段，不使用[CrossPred JSON](#crosspred-json) 的规范输出形状。

包界限实例的两侧环境字符串分别记为 `envRJson`、`envEJson`：

```json
{"packetBase":"v32:4","packetEnd":"add32(v32:4,v32:5)"}
```

```json
{"packetBase":"v32:4","packetEnd":"add32(v32:4,128)"}
```

测得的 Taken 谓词 `boundRT`、`boundET` 分别为：

```json
{"kind":"branch","position":10,"dir":"taken","width":32,"cond":{"lhs":"add32(v32:4,v32:5)","rel":"ltu","rhs":"add32(v32:4,14)"}}
```

```json
{"kind":"branch","position":6,"dir":"taken","width":64,"cond":{"lhs":"id64(add64(id64(zext32/64/32(extract0,32(v32:4))),14))","rel":"gtu","rhs":"zext32/64/32(extract0,32(add32(v32:4,128)))"}}
```

`exportCrossPredNormalize envRJson boundRT` 与 `exportCrossPredNormalize envEJson boundET` 返回相同字节，恰为[CrossPred JSON](#crosspred-json) 中已列出的 Taken `packetBound` 规范字符串。

返回 `1` 的 `ret32`、`ret64` 输入分别为：

```json
{"kind":"ret","width":32,"term":"1"}
```

```json
{"kind":"ret","width":64,"term":"1"}
```

`exportCrossPredNormalize envRJson ret32` 与 `exportCrossPredNormalize envEJson ret64` 均返回 `{"kind":"ret","payload":{"kind":"c","value":"1"}}`。这些环境解析、规范字节相等与失败实例由 `CrossPred.lean` 的有限 `#guard` 覆盖，不替代跨架构语义对应的证明。

### CrossPred JSON

`renderCrossPredJson : CrossPred → String` 输出紧凑 JSON，不附带载体、程序位置、动态事件或 Expr。字段按以下列出的顺序输出；数组保持内部顺序和重复项，数值不带前导零。全部自然数采用 JSON 整数，任意精度整数常元采用规范十进制字符串，host 须无损保存这两种数值。

五个外层形状的字段顺序为：

- helper：`kind:"helper"`、`observation`。
- branch：`kind:"branch"`、`dir:"taken"|"notTaken"`、`cond`。
- ret：`kind:"ret"`、`payload`。
- mapWrite：`kind:"mapWrite"`、`mutation`。
- packetWrite：`kind:"packetWrite"`、`packet`、`offset`、`value`。

`observation` 的三个形状依次为 `kind:"lookup",map,key`，`kind:"mutation",mutation`，`kind:"other",helperId,args`。规范化得到的 Helper mutation 统一提升到外层 `mapWrite`；直接构造的 `CrossHelper.mutation` 仍有上述渲染形状。`mutation` 固定为 `action:"write"|"delete",map,key,offset,value`。`key`、`args` 均为项对象数组。写入 `value` 为 `kind:"bytes",values` 或 `kind:"source",term`，两个形状保留独立标签。

`cond` 形状为 `kind:"plain",rel,lhs,rhs`，`kind:"packetBound",base,rel,offset`，或 `kind:"packetField",field,rel,value`；`packetField.value` 是十进制整数字符串。`rel` 固定为 `kind,q`，其中 `kind` 使用[规范关系族](../Predicate/跨架构谓词.md#项与关系)的名称。

项对象的字段顺序为：

- 常元：`kind:"c",value`，例如 `{"kind":"c","value":"-16"}`。
- 变元：`kind:"var",name`。
- 寄存器项：`kind:"reg",class,alpha`，`class` 按 Real、Stack、Map、Packet、Context 分别为 0、1、2、3、4；Map 的 `alpha` 是已去查询命名空间的偏移。
- 应用：`kind:"app",op,params,args`。`op` 使用 `CrossOp` 名称；`params` 依其构造参数顺序保存自然数。无参数标签输出空数组，`and/or/xor/low` 输出 `[q]`，`inputByte` 输出 `[resource]`，`extract` 输出 `[offset,length]`，`zext/sext/bswap` 输出 `[q,input]`，`mergeLow` 输出 `[q,bits]`。
- 外部结果：`kind:"external",lane,args`。

两侧测得 Taken 包界限的规范字符串均为：

```json
{"kind":"branch","dir":"taken","cond":{"kind":"packetBound","base":{"kind":"var","name":4},"rel":{"kind":"ltu","q":32},"offset":{"kind":"app","op":"add","params":[],"args":[{"kind":"var","name":4},{"kind":"c","value":"14"}]}}}
```

NotTaken 使用 `dir:"notTaken"` 和关系 `{"kind":"geu","q":32}`。返回 `1` 的两种载体均输出：

```json
{"kind":"ret","payload":{"kind":"c","value":"1"}}
```

相等输入的渲染字节由纯函数保持；测得 Taken 对的字节一致性另有有限 `#guard`。线协议不携带 CP-End、CP-Q 或资源对应的证明，语义判断边界仍由[跨架构待证明义务](../Predicate/跨架构谓词.md#待证明义务)约束。
