# T0 控制路径展开

T0 以带原槽号的 eBPF 汇编字符串列表为输入，将其中能够直接处理的向前控制流展开为若干文本路径。T0 只处理路径划分，不解释寄存器、栈、helper、packet、map 或算术语义，也不定义这些路径对应的机器执行状态。T0 不重新编号原始指令：每条原始汇编行携带的槽号称为 `index`，T0 产生的附加文本仍使用对应原始指令的 `index`；`index` 只表示信息来源于哪一个原始槽位，不表示转换后文本中的程序计数器。

形式化接口记为 `Parameter t0 : list string -> list (list string).`

## T0.1 输入与 `index`

输入是一组按原始槽号严格排列的汇编文本，每一条必须携带唯一的 `index`，基本格式为 `(?<index>\d+):\s+.+`。多槽指令只以其真实指令入口的 `index` 表示，中间槽不能作为控制流目标；同一个 `index` 不能对应两条不同的原始指令。条件跳转识别为 `(?<index>\d+):\s+if\s+(?<exp>.+)\s+goto\s+(?<path>.+)`，其中 `exp` 是条件表达式，`path` 按原始汇编跳转规则确定唯一目标 `index`。无条件跳转同样必须能唯一解析目标，且所有跳转目标都必须落在真实指令入口。目标 `index` 大于当前指令时称为向前控制，否则称为 backward control；T0 只展开向前控制。原始指令在多条展开路径中被复制时，每一份副本仍使用相同的 `index`。

改写前：

```text
15: r1 = r6
16: r1 += 0xe
17: if r1 > r2 goto +0x4 <xdp_prog+0x58>
18: w0 = *(u16 *)(r6 + 0xc)
```

改写后：

```text
15: r1 = r6
16: r1 += 0xe
17: assert (r1 > r2) == false
18: w0 = *(u16 *)(r6 + 0xc)
```

（上例仅示意 fallthrough 一侧：`17` 的 `if` 被同 `index` 的 `assert` 替换，编号不变。）

## T0.2 普通指令与 `exit`

T0 从输入入口开始处理。普通指令不改写，原字符串直接进入当前路径，然后继续下一条原始指令。`exit` 原样加入当前路径并结束该路径。

改写前：

```text
12: r6 = r1
13: w2 = *(u32 *)(r6 + 0x4)
57: exit
```

改写后：

```text
12: r6 = r1
13: w2 = *(u32 *)(r6 + 0x4)
57: exit
```

## T0.3 向前条件跳转

对于 `<index>: if <exp> goto <target>`，若 `<target>` 位于当前指令之后，T0 产生 taken 与 fallthrough 两组路径。原始向前 `if` 删除，仅写入同 `index` 的路径条件：taken 为 `assert (<exp>) == true` 后从真实跳转目标继续；fallthrough 为 `assert (<exp>) == false` 后从下一条原始指令继续。`assert` 不属于输入中的 eBPF 指令，只记录该路径对原条件跳转所选方向。T0 固定先产生 taken 的全部结果，再产生 fallthrough 的全部结果；内部若再遇向前条件跳转则同样递归展开，结果组合为 `taken_paths ++ fallthrough_paths`。因此若输入不含 backward 条件跳转，输出路径中不再出现 `if … goto …`。

改写前：

```text
17: if r0 == 0x0 goto +0x3 <xdp_prog1+0x148>
18: r1 = *(u64 *)(r0 + 0x0)
21: w0 = 0x1
```

改写后：

```text
17: assert (r0 == 0x0) == true
21: w0 = 0x1

17: assert (r0 == 0x0) == false
18: r1 = *(u64 *)(r0 + 0x0)
```

## T0.4 向前无条件跳转

对于向前 `<index>: goto <target>`，原始 `goto` 保留在当前路径中，之后不按文本下一条继续，而直接从真实目标处理；被跨过的指令不进入该路径。

改写前：

```text
20: goto +0x4 <xdp_prog+0x68>
21: w1 = *(u8 *)(r4 + 0x9)
25: r4 = r6
```

改写后：

```text
20: goto +0x4 <xdp_prog+0x68>
25: r4 = r6
```

## T0.5 backward control

目标不在当前 `index` 之后的条件跳转与无条件跳转不由 T0 展开：原始字符串保持不变，不沿 backward target 递归，也不生成循环展开。含这类控制的输出仍只是部分完成的路径划分；循环次数、循环条件或 backward 执行关系均不属于 T0。

改写前：

```text
31: if r1 != 0 goto -0x8 <loop>
32: r0 = 0x1
```

改写后：

```text
31: if r1 != 0 goto -0x8 <loop>
32: r0 = 0x1
```

## 证明义务

T0 当前只证明字符串形式转换本身明确且可逆，不要求建立 eBPF 指令与现实机器状态之间的执行语义。设 `T0Input : list string -> Prop` 与 `T0Output : list (list string) -> Prop` 分别描述合法输入与输出。

`T0Input` 至少要求：每条输入有合法且唯一的 `index`；原始指令按 `index` 严格排列；所有控制指令可唯一识别；所有跳转目标可唯一解析且只落在真实指令入口；每个需继续处理的位置有明确后继；每一条非向前条件跳转的原始指令至少出现在一条输出路径中，向前条件跳转以同 `index` 的 `assert` 出现。

`T0Output` 至少要求：每条非 `assert` 文本能按 `index` 唯一还原为一条原始输入指令；同一 `index` 的非 `assert` 字符串在不同路径中一致；`assert` 只出现在对应向前条件跳转的 `index`，且该 `index` 不再保留原始 `if`；taken 与 fallthrough 排列符合固定顺序；整个结果可由唯一合法输入经 T0 得到。

证明层引入 `Parameter t0_restore : list (list string) -> list string.`，只用于描述可逆性。恢复时收集所有非 `assert` 文本（同 `index` 副本须一致）；对仅以 `assert (<exp>) == true/false` 出现的 `index`，由 `exp` 与 taken/fallthrough 后继还原唯一向前条件跳转；最后按 `index` 排列得到唯一 `list string`。

改写前：

```text
17: assert (r0 == 0x0) == true
17: assert (r0 == 0x0) == false
```

改写后：

```text
17: if r0 == 0x0 goto +0x3 <xdp_prog1+0x148>
```

主要目标是正向转换与逆向恢复在各自合法域上互为逆：

```coq
Theorem t0_restore_t0 :
  forall p, T0Input p -> t0_restore (t0 p) = p.

Theorem t0_t0_restore :
  forall ps, T0Output ps -> t0 (t0_restore ps) = ps.
```

由此可得 `t0` 与 `t0_restore` 在合法域上的单射性。T0 不依赖现实执行状态；后续阶段分别作用于每条 `list string`，如何解释或改写 `assert` 及其他文本不属于 T0。
