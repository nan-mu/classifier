# T0：控制路径展开

T0 以带原始槽号的 eBPF 汇编字符串列表为输入，将其中能够直接处理的向前控制流展开为若干线性的文本路径。T0 只处理控制流，不解释寄存器、栈、helper、packet、map 或算术语义。输入中的每条原始汇编指令都携带唯一槽号，本文统一称为 `index`；T0 不重新编号原始指令，后续生成的附加文本同样沿用其来源指令的 `index`。`index` 只表示某条文本来源于哪个原始槽位，不表示转换后文本中的程序计数器。

T0 的接口为：

```coq
Parameter t0 : list string -> list (list string).
```

输入中的原始指令按照 `index` 严格排列，每一个 `index` 只能对应一条原始指令，多槽指令只使用真实指令入口的 `index`，中间槽不能成为控制流目标。基本输入形式满足：

```regex
(?<index>\d+):\s+.+
```

条件跳转按照：

```regex
(?<index>\d+):\s+if\s+(?<exp>.+)\s+goto\s+(?<path>.+)
```

识别，其中 `exp` 保存条件表达式，`path` 按原始 eBPF 跳转规则解析为唯一目标 `index`；无条件跳转同样必须能够唯一确定目标。若目标位于当前指令之后，则称为 forward control；否则称为 backward control。T0 只展开 forward control，backward control 原样保留并终止当前方向上的进一步控制流展开。普通指令直接进入当前路径，`exit` 直接进入当前路径并结束该路径。

## T0.1 Forward conditional control

T0 遇到向前条件跳转时，将当前路径划分为 taken 与 fallthrough 两个方向。原始 `if` 不再进入任何输出路径，因为完成路径划分以后，其仍然需要保留的信息已经由路径位置和新生成的 `assert` 完整表示：taken 路径生成 `<index>: assert (<exp>) == true`，随后从跳转目标继续；fallthrough 路径生成 `<index>: assert (<exp>) == false`，随后从原条件指令的下一条真实指令继续。两个 `assert` 都沿用原条件跳转的 `index`，其中表达式 `<exp>` 必须逐字来自原条件指令，不在 T0 中进一步解释或改写。

每个方向随后继续按照相同规则递归展开，因此一个条件跳转可以产生多条 taken 路径和多条 fallthrough 路径。T0 固定首先输出 taken 方向递归得到的全部路径，再输出 fallthrough 方向递归得到的全部路径，即结果始终按照 `taken_paths ++ fallthrough_paths` 排列。由此，同一输入不会因为遍历顺序或实现细节产生不同的路径排列。

重写前：

```text
15: r0 = MapLookupElem(V), r1 r2 r3 r4 r5 = UB
16: if r0 == 0x0 goto +0x3 <xdp_prog1+0x148>
17: r6 = r0
18: r1 = 0x1
19: goto +0x2 <xdp_prog1+0x150>
20: r0 = 0x2
21: exit
```

重写后：

```text
[
  [
    15: r0 = MapLookupElem(V), r1 r2 r3 r4 r5 = UB
    16: assert (r0 == 0x0) == true
    20: r0 = 0x2
    21: exit
  ],
  [
    15: r0 = MapLookupElem(V), r1 r2 r3 r4 r5 = UB
    16: assert (r0 == 0x0) == false
    17: r6 = r0
    18: r1 = 0x1
    19: goto +0x2 <xdp_prog1+0x150>
    21: exit
  ]
]
```

因此，T0 输出中不再保留已经成功展开的 forward conditional instruction。后续阶段只需要读取 `assert` 即可知道当前线性路径在该条件位置选择了哪一个方向，不需要再次解释原始 `if`。

## T0.2 Forward unconditional control

普通指令不发生改写并直接进入当前路径。遇到向前无条件跳转时，原始 `goto` 仍然保留在当前路径中，但控制流不再顺序进入文本中的下一条指令，而是直接从解析出的真实目标继续；因此，被该 `goto` 跨过的原始指令不会自动出现在当前路径中。遇到 `exit` 时，`exit` 原样进入当前路径并立即结束该路径。

目标位于当前 `index` 之前或等于当前 `index` 的条件跳转和无条件跳转属于 backward control。T0 不沿 backward target 继续递归，也不尝试展开循环次数或循环条件。由于 backward conditional 没有被 T0 展开，因此这种 `if` 仍然保持原始字符串；只有已经成功处理的 forward conditional instruction 才会被替换为 `assert`。因此，输出路径可能仍然包含 backward control，这表示 T0 只完成了当前定义范围内的 forward control 展开。

重写前：

```text
28: r1 += -0x1
29: if r1 != 0x0 goto -0x4 <loop>
30: goto +0x2 <done>
31: r0 = 0x1
32: r0 = 0x2
33: exit
```

重写后：

```text
28: r1 += -0x1
29: if r1 != 0x0 goto -0x4 <loop>
30: goto +0x2 <done>
33: exit
```

其中 `29` 属于 backward control，因此保持不变且不沿 backward target 展开；`30` 属于 forward unconditional control，因此保留 `goto` 文本并直接从目标 `33` 继续。



## 证明义务

T0 当前只证明字符串形式的控制路径转换本身是确定且可恢复的，不要求建立 eBPF 指令与现实机器状态之间的执行语义。对于满足当前输入约束的程序，每一条原始指令具有唯一且保持不变的 `index`，每一个 forward control target 也能够唯一解析为目标 `index`。因此 T0 虽然会在展开 forward conditional 时删除原始 `if`，但并没有删除恢复该控制关系所需要的信息：条件表达式保存在同 `index` 的 `assert` 中，taken 与 fallthrough 的后继位置则直接保存在展开后的路径结构中。

设：

```coq
T0Input  : list string -> Prop
T0Output : list (list string) -> Prop
```

`T0Input` 至少要求每一条输入文本具有合法且唯一的 `index`，原始指令按照 `index` 严格排列，所有控制指令均能够唯一识别，所有跳转目标均能够唯一解析并且只能落在真实指令入口。对于 forward conditional：

```text
<index>: if <exp> goto <target>
```

`<target>` 必须唯一对应一个真实目标 `index`；对于 fallthrough，也必须存在唯一的顺序后继。若证明要求恢复逐字符串完全相同的原始输入，则控制目标的文本表示还必须是由 source `index` 与 target `index` 唯一决定的规范形式，从而恢复目标 `index` 后即可唯一重建原始 `if` 字符串。

`T0Output` 至少要求所有非 T0 附加文本都能够通过其 `index` 对应到唯一的原始指令，同一个 `index` 在不同路径中出现时字符串必须一致；T0 新增的文本只能具有：

```text
<index>: assert (<exp>) == true
```

或：

```text
<index>: assert (<exp>) == false
```

两种形式。每一个这样的 `assert` 都必须唯一来源于同 `index` 的一个 forward conditional，并且同一个条件的 true 与 false 两个方向必须能够在输出路径集合中唯一配对。true 路径在该 `assert` 之后进入原条件跳转的 target，false 路径在该 `assert` 之后进入原条件跳转的顺序后继。由于所有原始 `index` 在 T0 前后保持不变，因此 source、target 与 fallthrough successor 都可以直接由输出路径中的 `index` 恢复。

证明层引入逆向函数：

```coq
Parameter t0_restore :
  list (list string) -> list string.
```

`t0_restore` 不属于实际分类流程，只用于描述和证明 T0 的信息保持性质。恢复时首先合并不同路径中重复出现的原始指令；同一个 `index` 的重复副本必须完全一致，只保留一份。随后处理由 T0 引入的 `assert`。例如输出中存在：

```text
17: assert (r0 == 0x0) == true
20: ...
```

以及：

```text
17: assert (r0 == 0x0) == false
18: ...
```

则两个 `assert` 具有相同的 `index = 17` 和相同的条件表达式，并且分别具有唯一的后继 `20` 与 `18`。因此可以唯一恢复原始 forward conditional：

```text
17: if r0 == 0x0 goto 20
```

其中 `17` 直接来自 `assert` 的 `index`，条件表达式直接来自 `assert`，target `20` 来自 true 路径的后继，而 false 路径的后继 `18` 用于验证该条件的 fallthrough 与原始顺序关系一致。恢复完成后删除对应的 true/false `assert`，将恢复出的 `if` 与其他原始指令按照 `index` 重新排列，得到唯一的：

```text
list string
```

因此 T0 最主要的证明目标仍然可以写成左逆性质：

```coq
Theorem t0_restore_t0 :
  forall p,
    T0Input p ->
    t0_restore (t0 p) = p.
```

也就是说，对于任意合法输入，T0 即使将 forward conditional 从输出路径中删除并替换为 `assert`，其保留的信息仍然足以唯一重建该 `if`，因此展开后再恢复必须严格得到原始输入。

该左逆立即给出 T0 的单射性：

```coq
Corollary t0_injective :
  forall p1 p2,
    T0Input p1 ->
    T0Input p2 ->
    t0 p1 = t0 p2 ->
    p1 = p2.
```

即两个不同的合法输入不能经过 T0 得到完全相同的路径集合。否则对相同输出应用 `t0_restore`，将同时得到 `p1` 与 `p2`，与左逆性质矛盾。

反方向还需要限制合法的 `T0Output`。任意声称属于 `T0Output` 的路径集合，其重复原始指令、`assert` 配对、taken successor、fallthrough successor 以及路径排列都必须满足 T0 的生成规则。特别地，一个 `assert true` 不能对应多个不同 target，一个 `assert false` 不能对应多个不同 fallthrough successor，同一 `index` 也不能同时恢复出两个不同的条件表达式。在该合法域上，可以进一步要求：

```coq
Theorem t0_t0_restore :
  forall ps,
    T0Output ps ->
    t0 (t0_restore ps) = ps.
```

也就是说，一个合法的 T0 输出恢复为原始输入以后，再执行一次 T0，必须得到完全相同的 `list (list string)`，包括各条路径中的文本以及 taken 在前、fallthrough 在后的固定排列。

由此还可以得到：

```coq
Corollary t0_restore_injective :
  forall ps1 ps2,
    T0Output ps1 ->
    T0Output ps2 ->
    t0_restore ps1 = t0_restore ps2 ->
    ps1 = ps2.
```

因此，在 `T0Input` 与 `T0Output` 所规定的合法域内，`t0` 与 `t0_restore` 构成严格的一一对应。T0 删除 forward `if` 并不意味着丢失控制信息；保持不变的 `index`、由 `assert` 保存的条件表达式，以及展开后路径中明确的 taken 与 fallthrough 后继共同构成了恢复该 `if` 所需的全部信息。后续阶段只需要处理 T0 输出的线性路径，不需要重新解释已经完成展开的 forward conditional control。
