# T0：控制路径展开

> **现状**：实现是 `src/rv32/t0.rs`。表面语法为 bpftool 方言（`wN`）。向前 `if` → `assert`（taken 先于 fallthrough）；向后/自环 `if` 保留原文并从下一条继续；无条件 `goto` 保留原文并**始终**进入目标（与 BPF 向后 goto 不同，见 T0.2）。可达 `trap` 使 T0 失败。

T0 将 lower（原 T-1）产出的 `Op` 表展开为有序的字符串路径，保留每条指令的原始 index。它不解释 packet、map 或返回值。接口为 `t0 : list string -> option (list (list string))`，每条输出路径由 `GT0 : list string -> bool` 检查，整个输出另外通过 `GT0Family` 检查。

## T0.1 条件分支与路径顺序

从 `Γ.entry` 出发，普通指令进入当前路径并沿唯一顺序后继继续；条件指令分为 taken 和 fallthrough，两边分别用同 index 的 `assert (<exp>) == true` 与 `assert (<exp>) == false` 代替原 if。`<exp>` 沿用 T-1 的规范表达式，尤其不能丢掉 `u32`、`s32`，也不能将 unsigned less-than 与 signed less-than 混用。递归完成 taken 的所有后继路径后，再输出 fallthrough 的所有后继路径，因而排序是深度优先的 `taken_paths ++ fallthrough_paths`。共享后缀在不同路径中重复出现，不合并列表元素；即使两条路径最终字符串相同，也不去重。T0 不做条件可满足性剪枝，不把语法路径数称为实际执行数。下例是取自样例控制结构的局部闭合片段，为展示完整路径而省略了本来位于这些入口之间的普通指令。

处理前：

```text
47: x10 = 0x1
48: if x11 == 0x0 goto 52
49: x12 = load_le32(x11)
50: x12 = add32(x12, 0x1)
51: store_le32(x11, x12)
52: exit
```

处理后：

```text
[
  [47: x10 = 0x1,
   48: assert (x11 == 0x0) == true,
   52: exit],
  [47: x10 = 0x1,
   48: assert (x11 == 0x0) == false,
   49: x12 = load_le32(x11),
   50: x12 = add32(x12, 0x1),
   51: store_le32(x11, x12),
   52: exit]
]
```

## T0.2 向后跳转与真正的循环

无条件 goto 原地保留，随后按其目标继续，与目标 index 大小无关。为保证有限展开，本阶段要求从入口可达的、已将受契约保护的调用折叠后的控制流图无环；可以用 DFS 递归栈或拓扑排序检查，只有重新进入当前递归栈中的节点才构成环。已访问但不在当前递归栈中的共享后缀不是循环。真实回边形成可达环时，本版本返回 `None`，不继续顺序执行、不任意展开一次，也不把预算耗尽后的截断路径作为完整结果。未来若引入有界循环展开，必须另行规定迭代次数、重复 index 的 occurrence 身份及相应守卫，不能悄悄改变本阶段。

样例 `34` 的 taken 目标是 `73`，`74` 又跳到 `36`，而 `36` 的后继不会回到 `34`，所以这是地址向后但图无环的路径。直接复制 BPF 的 backward-control 处理会漏掉 map 调用及后续返回。下例中的省略号仅为展示未变化的指令序列，不是输入语言；真实路径仍包含这些入口。输出顺序体现 taken 在先，即使 taken 路径内的 index 下降。

处理前：

```text
34: if u32(x11) >= u32(x12) goto 73
35: x10 = 0x0
36: store_le32(x2, x10)
... 37 至 71 的普通指令、受契约保护的调用和分支 ...
72: exit
73: x10 = zext32(load_le8(add32(x10, 0x6)))
74: goto 36
75: trap IllegalInstruction
```

处理后：

```text
taken-prefix:
34: assert (u32(x11) >= u32(x12)) == true
73: x10 = zext32(load_le8(add32(x10, 0x6)))
74: goto 36
36: store_le32(x2, x10)
... 从 37 继续展开，各条路径在 72: exit 结束 ...

fallthrough-prefix:
34: assert (u32(x11) >= u32(x12)) == false
35: x10 = 0x0
36: store_le32(x2, x10)
... 从 37 继续展开，各条路径在 72: exit 结束 ...
```

## T0.3 调用、返回与不可达入口

带契约的 `call C` 作为一个保留副作用的抽象节点进入路径，并沿契约规定的正常返回入口继续；T0 不进入外部函数，也不删除 link 效果。只有契约保证本支持域内正常返回时才允许这种单后继处理；可能不返回、抛出异常或跳转至多个 continuation 的调用需要扩充模型，否则拒绝。内部函数调用本版同样只接受已有摘要契约，不隐式内联。`exit` 进入路径并终止，不继续读取物理布局中的下一条指令。因此 72 后面的 73、74 可以通过其他分支到达，75 却不会因文本相邻而进入任一返回路径。可达 `trap`、未解析 indirect 或无合法终结的落空后继均使 T0 失败；不可达且已准确解码的 trap 可保留在原程序表，不出现在路径族里。由此本阶段不承诺从输出恢复不可达指令，更不承诺恢复完整二进制。

处理前：

```text
44: x1 = pc_rel(0x6e5080)
45: call C45 target=pc_rel(0x6e4a5c) link=x1:pc_rel(0x88) next=46
46: x11 = x10
... 后继子图，均终于 72 ...
72: exit
75: trap IllegalInstruction
```

处理后：

```text
44: x1 = pc_rel(0x6e5080)
45: call C45 target=pc_rel(0x6e4a5c) link=x1:pc_rel(0x88) next=46
46: x11 = x10
... 当前分支选择的后继路径 ...
72: exit
```

## T0.4 输出守卫与样例结果

`GT0(p)` 以 `Γ` 中的原程序表为证据，检查 p 从入口开始、每个相邻入口满足对应边关系、条件边由正确 assert 表示、所有 index 均来源唯一、调用契约有效、末尾恰为一个合法 exit，并检查路径内不存在重复入口或残余 if/indirect/trap。不能要求 index 单调递增，否则会错误拒绝 `34,73,74,36`。`GT0Family(ps)` 在相同有限 DAG 上重新核对整个展开树，保证每个条件两边均出现、taken 子树在先、普通边不遗漏、共享后缀复制正确；单独对每条路径调用 GT0 不足以证明覆盖性。资源上限只能导致显式失败，不能在路径族守卫中忽略未输出分支。样例路径数 63 由 `tests/rv32_pipeline.rs` 对 `example/esp32c3.bin` + `config/esp32c3.environment.toml` 复核；仍以 `C45` 正常返回及其余环境契约为前提。

处理前：

```text
entry=0; return=72; call45.next=46
conditional-indices=[9,13,15,17,24,26,29,34,48,54]
goto-edges=[20->22,31->36,74->36]
unreachable=[75]
```

处理后：

```text
syntactic-paths=63
paths-containing-edge(74,36)=12
reachable-control-graph=acyclic
forall p in paths: last-index(p)=72
GT0Family(paths)=true  # 仅在上述布局、调用和返回契约已成立时
```

## 证明义务

证明有限 DAG 上的终止性、taken-first 确定性、每条路径边合法，以及路径族完整覆盖图中的所有入口到退出路径。assert 保留原分支条件，调用摘要保持契约允许的行为。证明只恢复可达的规范控制图；不可达入口、原汇编拼写和原字节不在左逆承诺内。当前没有相应 Rocq 定理。
